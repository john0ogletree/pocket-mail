# pocket-mail

A lightweight, zero-dependency, local-first mail server architecture built for total self-reliance and privacy. Run your own custom domain email server without monthly SaaS fees, heavy cloud infrastructure, or corporate lock-in.

---

## 💡 Philosophy

Modern self-hosting often pushes users toward complex server clusters or paid third-party email APIs. This project proves that with modern, composable open-source software, you can achieve **full email control on zero budget**:

* **Zero SaaS Dependencies:** No proprietary mail services, API lock-ins, or monthly subscription fees.
* **Local-First Architecture:** Your emails, user credentials, and database remain strictly local on your own hardware.
* **Minimal Footprint:** Single-binary operation using lightweight, auditable open-source software.
* **Total Sovereignty:** You own your configuration, local storage, and private key material.

---

## 🛠️ Architecture Overview

* **Core Mail Server:** [Maddy Mail Server](https://maddy.email/) — a modern, single-binary, memory-efficient SMTP/IMAP server.
* **Protocol Support:** Standard SMTP for message transfer and IMAP for local mail client access.
* **Database & Storage:** Embedded SQLite database driver for zero-dependency local account and state management.
* **Security & Authentication:** Full support for domain-level security standards:
  * **SPF** (Sender Policy Framework)
  * **DKIM** (DomainKeys Identified Mail)
  * **DMARC** (Domain-based Message Authentication, Reporting, and Conformance)

## 🚀 Quick Start & Setup

### 1. Prerequisites
* A unix-like environment (Linux, macOS, BSD, or mobile terminal environments).
* A registered domain name with access to update DNS records.
* The [Maddy binary](https://maddy.email/) compiled or installed for your architecture.

### 2. Configuration
Copy the example configuration file to create your local runtime config:

```bash
cp maddy.conf.example maddy.conf
```

Edit `maddy.conf` to replace placeholders with your actual domain settings:
* Replace `example.com` with your primary domain.
* Configure your local directory paths for state and SQLite storage.

### 3. DNS Setup
Add standard DNS records with your domain registrar:
* **MX Record:** Points to your server address.
* **SPF (TXT):** Authorizes your server instance to send mail.
* **DKIM (TXT):** Generated by Maddy during initialization for cryptographic message signing.
* **DMARC (TXT):** Defines handling policy for unauthenticated messages.

### 4. Background Execution
Run Maddy in persistent background mode:

```bash
nohup ./maddy -config maddy.conf run > maddy.log 2>&1 &
```

Verify startup in the log file:

```bash
tail -f maddy.log
```

## 🛡️ Security & Privacy Notice

Never commit your active `maddy.conf`, private DKIM keys, log files, or SQLite databases (`*.db`) to public version control. Ensure all sensitive files are listed in your local `.gitignore`.
